# 3DsVW — 3D Source Map Viewer

3DsVW is CS2MB's browser-based, read-only 3D technical viewer. It displays the
collision geometry, NAV data, entities and representative routes generated by
the map preparation pipeline. It does not load the game's render world,
materials or textures.

## Role in CS2MB

The viewer is available inside the application and in a separate browser tab.
Both use the same local assets and generated map bundle. It is a presentation
layer: changing layers or camera state never changes analysis results.

Data flow:

```text
map VPK
  -> prepare_map.py extracts NAV, EntityLump and world PHYS resources
  -> SRI converts EntityLump -> entities.txt
     and PHYS -> collision glTF + BIN
  -> auto_generate.py runs map analysis and build_viewer3d(...)
  -> out_dir/viewer3d/data.json + scene.gltf + scene.bin
  -> local app serves the bundle -> 3DsVW
```

`tools/auto_generate.py` calls `viewer3d.build.build_viewer3d` with the NAV file,
entity dump and collision glTF. The application reports the bundle through the
job result and serves it at `/viewer3d/<map>/<job>/`. Shared viewer code is
served from `viewer3d/assets/`; it is not copied into every map bundle.

## Bundle files

| File | Purpose |
|---|---|
| `data.json` | Viewer payload: NAV areas and edges, entity markers, routes, collision node/primitive metadata, bounds and statistics. Schema `cs2mb.viewer3d/1`. |
| `scene.gltf` | Normalized SRI collision glTF. Textures/images and external buffer references are removed. |
| `scene.bin` | Single binary buffer referenced by `scene.gltf`. |

The bundle is written through a staging directory and validated before replacing
the previous `viewer3d` directory. Incomplete bundles are not reported as valid.

## Data layers

### Collision Geometry

Collision comes from the PHYS block of `world_physics.vmdl_c`, converted by SRI
to a glTF triangle mesh in Hammer units and Source axes (`x`, `y`, `z-up`).
3DsVW separates collision faces into floors, walls and other surfaces by
orientation. Clip and sky collision is kept in a separate, hidden-by-default
layer. This is collision, not render geometry.

### NAV

NAV areas and directed connections are stored in `data.json`. The viewer builds
polygons and link lines from those coordinates. NAV is a navigation
representation, not proof that every link is traversable in game.

### Render Geometry

Render geometry, materials and textures are **not** part of 3DsVW. The viewer
does not read render meshes or VPK texture data, and it does not attempt to
reproduce the in-game appearance of a map.

### Entities and routes

Spawn points, objectives/places, markers and representative CT/T routes are
included in `data.json` with their available metadata. Route lines are analysis
output, not recorded player movement.

## Geometry, transforms, bounds and metadata

- SRI writes collision triangles in Source coordinates. The viewer applies glTF
  node transforms through three.js; the summary builder composes parent/child
  TRS or explicit matrices exactly once.
- Collision bounds, NAV bounds and aggregate scene bounds are stored separately
  in `data.json`. Fit, Top, Isometric and grid framing use aggregate scene
  bounds; camera padding is applied only by the viewer.
- glTF bounds are world-space transformed accessor AABBs and are conservative
  for rotation and non-uniform scale. The payload records this in `bounds_mode`.
  They are not exact post-transform mesh hulls.
- Collision metadata is tracked per primitive: material name and index, surface
  property, collision group, `InteractAs`, clip/sky state and triangle count.
  Legacy node-level fields remain available for compatibility.
- The viewer selects primitive metadata by material name with a node-level
  fallback. Duplicate node names keep distinct `node_index` identities in the
  payload.

## Build, run and use

The viewer itself does not have a separate build command or standalone
executable. It is built as part of map generation:

1. Prepare a map through the application's **Prepare + Generate** flow, or run
   `tools/prepare_map.py` followed by `tools/auto_generate.py` with the prepared
   NAV, `entities.txt` and collision glTF.
2. `auto_generate.py` writes the analysis outputs and the `viewer3d` bundle.
3. Start CS2MB with the packaged launcher or, from the repository,
   `python app\server.py`.
4. Open the generated job's 3D viewer in the application or in a separate tab.

The application serves both the shared viewer assets and the generated bundle.
Opening `viewer3d/assets/index.html` directly from disk is not supported because
the viewer uses ES modules and bundle-relative paths.

Controls include orbit, pan, zoom, Fit, Top, Isometric and Reset, plus layers for
collision surfaces, clip/sky volumes, NAV, entities and routes. Selecting
geometry or a marker shows available metadata in the inspector.

Direct CLI shape (verified against the scripts):

```text
python tools\prepare_map.py --map <map> --game <CS2 install> --out-dir <prepared>
python tools\auto_generate.py --map <map> --nav <map.nav> \
  --entities <entities.txt> --collision-gltf <world_physics_physics.gltf> \
  --out-dir <job-output>
```

`prepare_map.py` also supports `--generate-out`; use its `--help` for the
authoritative argument list.

## Capabilities and limitations

Capabilities:

- read-only collision, NAV, entity and route visualization;
- floor/wall/other separation and optional clip/sky layer;
- fit/top/isometric camera presets and layer controls;
- metadata inspector for collision primitives, NAV areas and entity markers;
- embedded and separate-tab modes using the same implementation;
- locally served assets with no CDN or runtime downloads;
- bounded input sizes and confined bundle paths.

Limitations:

- no render geometry, materials or textures;
- no map editing, measurement tools or box selection;
- conservative AABB bounds, not exact rotated mesh extents;
- NAV links are displayed as generated; the viewer does not simulate traversal;
- route timings remain estimates and are not a match-balance verdict;
- WebGL2-capable browser required;
- a generated bundle is required; the viewer is not a standalone map-file
  opener.
