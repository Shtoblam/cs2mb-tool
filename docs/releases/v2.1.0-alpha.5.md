# CS2 Map Balance 2.1.0-alpha.5 — branding and website milestone

**Tag:** `v2.1.0-alpha.5`

**Release range:** `v2.1.0-alpha.4..v2.1.0-alpha.5` (11 commits)

**Tag target commit:** `3b76d6805bac59ff9a1cc251a0a13cb952d29cd8` (documentation-only)

**Published:** 2026-11-21

**Type:** project milestone covering the website/product presentation redesign and
a small application branding integration

## What changed

- The static project website was rebuilt as a product-presentation site
  (`index.html`, `site.css`, `site.js`, website banners).
- The GitHub Pages workflow was updated.
- Application branding was integrated: `app/index.html` uses the local
  `/logo.png` asset, `app/server.py` adds the `/logo.png` route, and `logo.png`
  was added to the repository.
- `tests/test_app_ui.py` and `tests/test_server_security.py` gained regression
  coverage for the logo/favicon and logo route.
- Release, project-state and documentation files were updated.

## What did not change

- No map-analysis algorithm, navigation graph, collision calculation, movement
  model, simulation scenario or balance calculation was changed.
- The analysis scope remains time-only route and comparison indicators; there is
  no combat, detection/encounter simulation or win-rate model.
- The CS2 safety model remains local and read-only, with no game process or
  memory access.
- `VERSION` remains `2.1.0-alpha.4`. This milestone did not bump the application
  version.

## Tag versus release range

The commit pointed to by the tag is documentation-only. The complete release range
is not: it includes the application branding change, the `/logo.png` route and two
tests. Do not infer the scope of the release from the tag target commit alone.

The final `main` commit after this tag continued with documentation and website
changes; no application analysis code changed after the tag.

## Verification at publication

The published release stated that the application test suite was not rerun because
application and analysis code were not modified by this milestone. That statement
is not fully accurate for the release range because the branding route and tests
were included. This note does not retroactively claim additional verification.
Current repository checks are reported in [STATE.md](../STATE.md) and the
[changelog](../../CHANGELOG.md).
